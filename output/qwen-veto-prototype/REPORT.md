# Изолированный эксперимент: Qwen3.5 как фильтр актуальности C_syntax

Статус: **не внедрять** — на отложенной авторской выборке появился новый FN. Рабочий API, модели, генератор, экспорт и сервер Qwen не менялись; Git push не выполнялся. Дата: 16.11.2026.

## Протокол

- Кандидаты получены через работающий контрольный C_syntax на `127.0.0.1:18009`; порог и веса не менялись. Ветки `test-branch` и `test-branch-runtime` имеют расхождение хеша `syntax_features.py` с manifest старого C_syntax, поэтому **не перезапускали** работающий сервис и не выдавали повторную загрузку модели за идентичное воспроизведение.
- [verify_candidates.py](verify_candidates.py) — отдельная CLI-программа. Для просмотра evidence использует проверенный bundle H123 **только как замороженный энкодер и те же query-векторы** (SHA-256 `988e0d8f…`); H123 CatBoost **не** определяет кандидатов. Raw chunker, как в C_syntax. Дополнительно сохраняет Top-3 по каждому ID, соседние чанки (±1), ранние/поздние фрагменты с временными ограничениями и последние чанки текста. Если фрагменты не трассируются к оригиналу или превышен бюджет 17 000 символов, veto пропускается. Это реконструкция retrieval, а не доступ к внутреннему trace работающего сервиса: полное тождество рангов отдельно не доказано.
- Триггер — упоминания архива, прошлого, отказа, изменения специализации, текущего предложения и условий комплексного ремонта. Без него Qwen не вызывается. **Один** запрос к локальной Qwen на все предложенные категории, status из `CURRENT_OFFER`, `PAST_ONLY`, `CURRENT_REFUSAL`, `THIRD_PARTY`, `UNCERTAIN`. Сервер `/props` сообщил `/models/Qwen3.5-9B-Q8_0.gguf`, alias `avito-qwen`, контекст 32768.
- ID сверяются с входом, новых ID быть не может. Veto разрешён только для `PAST_ONLY`, `CURRENT_REFUSAL`, `THIRD_PARTY` при непустой **дословной непрерывной** цитате в исходном описании и переданном фрагменте. `UNCERTAIN` сохраняется; ошибка Qwen/формата/контекста — fail-open без изменения baseline. Для `CURRENT_OFFER` передаётся поле `constraint` (например, «только в составе комплексного ремонта»), но генератор рабочего API пока его **не получает**.
- До отложенной оценки составлены [development 11 объявлений](verifier_dev.jsonl) и [holdout 11 объявлений](verifier_holdout.jsonl), оба с авторскими вручную заданными метками; Private test не участвовал в настройке. На development после первого прогона добавлены три длинных авторских сценария, а затем один раз уточнено требование к непрерывной цитате (вместо склейки с «…»). После этого код заморожен: SHA-256 `d62c3392c9001f091335e8590fd4efbdde441ac1adcbf42e4a1d89e460aceb4c`. Holdout после фиксации правил использован однократно. Это **малый авторский набор**, а не независимая человеческая разметка реального трафика; сценарии родственны и не могут подтверждать production-выигрыш.

## Задержка

Development: Qwen вызвана в 6/11 случаях, медиана **869 мс** среди вызванных (598–2586 мс). Holdout: 7/11, медиана **747 мс** (649–1937 мс). Классификация через HTTP baseline: медиана ~19 мс на этих коротких/авторских текстах, но скрипт **дополнительно пересчитывает embeddings для evidence**, а это время не выделено в сохранённой телеметрии. Поэтому числа Qwen — нижняя граница дополнительной задержки, **не** end-to-end и не p95 под нагрузкой. Один Qwen-вызов на все кандидаты при срабатывании триггера; кратность обращений к Qwen и долю триггеров на реальном потоке не измеряли.

## Private case-004: только диагностика после заморозки

Вход прочитан локально из CSV и передан программе через stdin; в репозиторий и отчёт исходный текст/ответ Qwen **не записывались**. Baseline `[102,104,106]`; после фильтра `[106]`, veto `[102,104]`; Qwen ~2023 мс, baseline HTTP ~714 мс (без повторного получения evidence). Это успешный отдельный диагноз, **не** отбор правил и не независимая метрика. На нём нельзя подбирать промпт/пороги.

Важная оговорка: для 104 Qwen указала статус `CURRENT_REFUSAL`, но приложенная цитата была из архивной части о прежних сотрудниках, а не из финального актуального отказа. Итоговый ID здесь правильный, однако это **провал проверки обоснования**: наличие дословной цитаты не доказывает, что она подтверждает заявленный статус. Такой ответ должен быть проверен дополнительно, прежде чем применять veto в продукте.

## Вывод и следующая проверка

Текущий вариант **не внедрять**: явный новый FN на отложенном сценарии при малом и искусственном наборе. Цитата в тексте необходима, но недостаточна для доказательства `CURRENT_REFUSAL`. Нужна отдельная проверка соответствия цитаты категории и охвата слов «остальные», «кроме», «только», не подгоняя правила по holdout или Private. Затем новый, заранее зафиксированный протокол с **новой независимой человеческой разметкой** обычных и сложных объявлений, оценкой FP/FN по категориям, p50/p95 полного пайплайна и ограничений генерации. Не обучать и не выбирать по Private test или текущему holdout.

Запуск для новых dev-данных (не повторять отбор по текущему holdout): `PYTHONPATH=/srv/Hakaton/innopolis_2026-test-branch-runtime /srv/Hakaton/transformer-venv/bin/python output/qwen-veto-prototype/verify_candidates.py --input <new.jsonl> --output <results.jsonl>` из корня репозитория. Требуется доступный локальный C_syntax на `18009` и Qwen3.5 на `8000`.
