# Почему public test хуже validation: проверка покрытия

**Вывод:** гипотеза частично подтверждается. В тесте есть новые текстовые шаблоны и слабо представленные сценарии. Но новых целевых категорий и сочетаний меток нет; некоторые пропущенные услуги много раз встречались в train. Разрыв связан также с близкими шаблонами внутри случайного public split, изменением состава теста и неоднозначной разметкой. Причинный вклад каждого фактора не установлен.

Проверена сохранённая public-only модель: word(1,3), char_wb(3,5), 18k+28k, SGD, пороги 0,5, только description. Train 3398, calibration 728, validation 729, официальный public test 208. **Обучение и подбор параметров не запускались**, источники и веса не редактировались. Это проверка публичных данных, не синтетики v2/v3 и не смешанной модели.

## Измеренные различия

| Показатель | Public train | Public validation | Public test |
|---|---:|---:|---:|
| Строк | 3398 | 729 | 208 |
| Micro-F1 | 0,99450 | 0,93712 | 0,81481 |
| Precision / Recall | 0,99280 / 0,99621 | 0,93866 / 0,93559 | 0,72368 / 0,93220 |
| FP / FN | 61 / 32 | 112 / 118 | 105 / 20 |
| Пустой gold | 946 (27,8%) | 203 (27,8%) | 106 (51,0%) |
| Медиана длины, символов | 1465 | 1468 | 1343 |
| Медиана доли слов, не встречавшихся в train | — | 0,71% | 1,28% |
| Медиана доли словесных биграмм, не встречавшихся в train | — | 9,67% | 20,69% |
| Новых сочетаний целевых меток | — | 0 | 0 |
| Ближайший train с cosine >= 0,8 | — | 281/729 (38,5%) | 32/208 (15,4%) |
| Медиана cosine до ближайшего train | — | 0,652 | 0,373 |

Cosine — сходство в существующем TF-IDF-пространстве, не семантическая оценка и не доказательство утечки. Порог 0,8 выбран как описательный срез, не для модели. Из train удалены точные нормализованные повторы, но близкие варианты текстов могут оказаться по разные стороны случайного split. Незнакомые слова считаются по всем наблюдавшимся train-токенам, а не только по ограниченному словарю модели.

| Сходство с ближайшим train | Validation: строк / F1 | Test: строк / F1 |
|---|---:|---:|
| < 0,5 | 319 / 0,87952 | 132 / 0,72922 |
| 0,5–0,8 | 129 / 0,93724 | 44 / 0,92857 |
| >= 0,8 | 281 / 0,98814 | 32 / 0,90566 |

Все 20 FN теста относятся к срезу <0,5. Там же 81 из 105 FP: всего 101 из 125 ошибочных решений по меткам (80,8%). Это связь ошибки с лексической непохожестью, **не доказательство**, что отсутствие похожих текстов вызвало все эти ошибки. На мало похожих текстах validation тоже хуже, однако разрыв с test сохраняется.

## Проверка конкретных услуг

Счётчики — поиск явно описанных лексических шаблонов, не полная семантическая разметка. Число положительных примеров означает совместное наличие маркера и соответствующей категории в gold.

| Услуга / маркер | Train с упоминанием | Из них с нужной меткой | Пропущенный пример test (индекс с 0) |
|---|---:|---:|---|
| Затирка (межплиточных) швов | 118 | 115 с 103 | 181: «Затирка межплиточных швов — Новотроицк»; score 103=0,251 |
| Крыльцо | 3 | 3 с 103 | 59: «Облицовка крыльца плиткой — Оренбург»; score 103=0,308 |
| Замена … плитки / плитка … замена, в пределах 35 символов | 70 | 41 с 103 | 125: «Ремонт и замена плитки — Оренбург»; score 103=0,266 |
| Колеровка | 2 | 2 с 106 | 114: «Выполняем колеровку…»; score 106=0,399 |
| Подбор краски / цвета / оттенка | 4 | 4 с 106 | Тот же 114 содержит подбор краски и оттенка, но в другой форме |

Услуги не полностью отсутствуют: затирка представлена широко, крыльцо и колеровка — очень слабо. В трёх пропущенных плиточных объявлениях основная услуга занимает короткую часть текста, далее одинаковый рекламный блок. Формулировка **«Организация работ:» встречается в 29 тестовых объявлениях и в 0 train / 0 validation**. Это подтверждённый новый поверхностный шаблон, не доказательство отсутствия семантически похожих объявлений. Предположение о подавлении сигнала услуги рекламным фоном требует отдельной абляции, здесь она не проводилась.

## Сложность задачи и разметка

1. **Ограничения на отдельные заказы.** Строка 103: «Отдельные мелкие задачи не берём, работаем с полноценным ремонтом под ключ». Gold пустой, модель добавляет все пять категорий со score 0,640–0,944. В train найдено 22 текста с узким маркером «только комплексно / только под ключ / отдельные задачи не берём», все с пустым gold. Значит, сценарий не отсутствует, но редок (0,65% train). Контекстное ограничение модель переносит плохо. Не всякое слово «комплексно» означает отказ от отдельных услуг.
2. **Разные правила выделения услуги / спорные метки.** Строка 32 перечисляет штукатурку, обои, плитку, электромонтаж и сантехнику, gold пустой; явного отказа от отдельных работ в прочитанном тексте нет. Строка 134: «штукатурка, шпатлёвка стен, укладка ламината», gold только 102, модель 102/103/106. Строка 106 о текстильных стенах имеет gold 105, но розетки/выключатели упоминаются как места аккуратных стыков, явного электромонтажа не найдено. Это кандидаты на независимую проверку, а не автоматически исправленные ошибки эталона.
3. **Фактические противоречия.** У одинакового нормализованного description в тесте 13 групп с разными gold, всего 56 строк. На них приходится 60 FP + 3 FN из общих 125 ошибок. При этом исключение этих групп даёт F1=0,81325: оставшиеся ошибки сохраняют разрыв. Нельзя объяснить всё только конфликтами.
4. **Пересечения.** 20 тестовых строк точно совпадают с train (F1=0,94737). Без них остаётся 188 строк с F1=0,80259. Дополнительная очистка от конфликтов, пересечений со всеми public splits и повторов даёт 114 строк, F1=0,74236. Это другой состав подвыборки, не новая оценка на репрезентативном тесте.
5. **Контракт.** Parquet содержит только title, description, categories; исходного mcId нет. Как и в прежних измерениях, принят source=101. Это ограничение оценки. В требованиях запрещено обещать отдельный заказ без основания; степень достаточности комплексного предложения для draft следует уточнять отдельно. Все пять категорий представлены в train: 102=1750, 103=1620, 104=1615, 105=1608, 106=1854 положительных строк.

## Что делать

- При следующей оценке разделять близкие шаблоны и сценарии группами; оставить отдельную validation на новых формулировках. Общие 0,937 на случайном split не считать прогнозом финального теста.
- Дополнять train разнообразными одиночными услугами внутри рекламного фона, редкими операциями и явным отказом от отдельных заказов. Писать новые сюжеты, не копировать тестовые тексты или найденный тестовый шаблон.
- Независимо проверить правила и спорные метки, особенно пустые ответы при перечне услуг; не исправлять их по предсказаниям модели.
- Не пытаться закрыть проблему общим снижением порога: часть FN имеет score 0,25–0,40, но контекстные FP уже достигают 0,94.

Источники: `summary.json` (метрики, счётчики и SHA-256), `test_examples.json` (полные тестовые тексты, ближайший train, метки и вероятности), `validation_neighbors.json` (построчная диагностика), `audit.py` и `finalize.py` (воспроизведение: PYTHONPATH=. python …). Полные промежуточные train/validation-тексты в `examples.json` локальные, в Git не включаются. Ни новых fit, ни семантической переразметки всех объявлений не проводилось.
