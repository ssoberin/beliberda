# Причина FP104/105 в public train 1060

Без изменения кода модели и без обучения. Полная трассировка: refusal_diagnosis.json.

В чанке «Электрику и сантехнику НЕ делаем (занимаемся исключительно чистовой и черновой отделкой)» собственный извлекатель даёт для каждой из 104/105 две связи:

- делаем → negated, частица НЕ найдена правильно;
- занимаемся → offered, ошибочно присвоено электрике и сантехнике вместо отделки.

Код `_analyze_sentence_for_category` расширяет список candidate_preds на связанные предикаты без достаточной проверки их собственного объекта. Это подтверждённый источник ложного положительного свидетельства, а не потеря отказа при retrieval. Агрегатор сохраняет offered вместе с negated; CatBoost получает syn_affirmative_offer=1 и syn_has_conflicting_claims=1.

| Категория | p_sgd | p_C_syntax | Gold |
|---|---:|---:|---|
| 104 | 0.497717 | 0.700710 | 0 |
| 105 | 0.225198 | 0.661248 | 0 |

SGD при 0.5 обе категории не добавлял; итоговый CatBoost добавил. Это наблюдение не является доказательством причинного вклада отдельного признака: для этого нужна отдельная абляция.

Предлагаемое исправление: сохранять связь «конкретная услуга — собственное действие — относящееся к нему отрицание»; переносить действие между частями предложения только при подтверждённом общем объекте или корректной анафоре. Отдельно проверять эллипсис, частичные отказы и «не только». Изменение значений существующих признаков требует контролируемой проверки сохранённой модели и корректного переобучения при изменении семантики признаков. Сейчас ничего из этого не внедрялось; качество после исправления не измерено.
