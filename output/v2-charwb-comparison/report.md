# char_wb на новом корпусе v2

Источник: main, commit 0b1be5d. Корпус скопирован без изменения в datasets/hard_dataset/v2. Старый public-train в main только перенесён, содержимое не изменилось.
Обучены с нуля три модели только на v2 train (8464). Готовые validation (2440), test (3016) и challenge (40) сохранены. Seed корпуса 2026; SGD random_state=42. Переразбиения и смешивания с public не было.
Триграммы (1,3), char_wb (3,5), sublinear_tf=True, исходные min_df и SGD; пороги всех категорий 0.5. Метки обучения: offered∩{102..106}. Оценка: found∩{102..106} после удаления исходной категории из предсказаний. Голова101 не добавлялась.

## Проверки и ограничения
- Проверены SHA-256 исходных файлов и неизменность подготовленных выборок.
- Проверены отсутствие одинаковых нормализованных effective descriptions и group_id между готовыми частями, согласованность offered/source/found.
- TF-IDF fit выполнялся только на train, метаданные и объяснения не попали в признаки.
- Независимая повторная оценка test из исходного v2 совпала с measurement для всех моделей.
- Существующие рабочие модели не заменены. Одиночные замеры времени приблизительны.
- После сравнения конфигураций этот test уже использован для выбора модели; для окончательной оценки нужен новый независимый набор.

Результаты EDA находятся в ../v2-eda/. Полные метрики/параметры: runs/summary.json; срезы и challenge: evaluation.json; происхождение и mapping: splits/stats.json.

Вывод: на данном v2 изменение лимита46k→60k→100k не меняет модель. Требуется разбор ошибок по формулировкам и проверка на смешанном реальном/сложном корпусе с независимым контролем; автоматически добавлять данные/менять архитектуру в этом эксперименте не стали.
