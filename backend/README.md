# Backend для генерации черновиков через Qwen

FastAPI принимает исходное объявление и выбранные категории, отправляет один
асинхронный запрос к удалённому Qwen и возвращает отдельные черновики в формате
frontend. Qwen должен обслуживаться через OpenAI-совместимый API, например vLLM.
Один только SSH-доступ к компьютеру с весами модели не заменяет запущенный API.

Python 3.11+. Все команды ниже выполняются из корня репозитория.

## Установка и запуск

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
```

Заполните backend/.env. SSH-подключение и ключи в Git не коммитятся.
Для настоящего подбора категорий установите путь к локальным весам первой TF-IDF:

```dotenv
CLASSIFIER_MODEL_PATH=/srv/Hakaton/models/baseline/tfidf_baseline.joblib
```

Артефакт хранится вне Git. Перед загрузкой joblib проверяется SHA-256
`668c95e2cecdaa2b94f1a82470e6b89fe3ab1808c765539b45291a22a15004bc`.
Другой файл не загружается, автоматического переобучения нет. Пять порогов — 0.5.
Без настроенного файла `/api/categories` отвечает 503, но ручной выбор
категорий и генерация остаются доступны. При неверном хеше запуск прерывается,
чтобы не загружать неподтверждённый pickle.

Для автоматического туннеля достаточно указать:

```dotenv
SSH_TARGET=qwen-server
SSH_REMOTE_HOST=127.0.0.1
SSH_REMOTE_PORT=8000
SSH_LOCAL_PORT=18000
QWEN_MODEL=avito-qwen
```

`qwen-server` — существующий алиас из ~/.ssh/config; можно использовать user@host.
SSH_PORT и SSH_IDENTITY_FILE необязательны: используются настройки OpenSSH и
ssh-agent. При заданном SSH_TARGET адрес Qwen по умолчанию:
http://127.0.0.1:18000/v1. Если переопределяете QWEN_BASE_URL, он должен указывать
на локальный порт туннеля. Имя QWEN_MODEL должно совпадать с ID модели сервера.

Обычное SSH-подключение с ключом должно уже работать, а ключ сервера — быть
проверен и сохранён в known_hosts. Backend запускает ssh без интерактивного
ввода пароля и с проверкой ключа сервера. Пароли через API не передаются.

```bash
backend/.venv/bin/python -m uvicorn backend.app.main:app \
  --host 127.0.0.1 --port 8001 --env-file backend/.env
```

Документация API: http://127.0.0.1:8001/docs.
При автоматическом туннеле используйте один worker: каждый процесс приложения
пытается занять SSH_LOCAL_PORT. Приложение открывает туннель при старте и закрывает
его при остановке. При недоступной сети приложение запускается с /health=200,
но /ready=503. После обрыва SSH и при неудачной начальной попытке backend
переподключается с задержками 1, 2, 4 секунды и далее до 30 секунд между попытками.
До восстановления генерация отвечает 503, не обращаясь к отсутствующему туннелю.
После восстановления сети ручной перезапуск не требуется. Отсутствие программы
ssh остаётся ошибкой запуска. Чужой процесс на локальном порту не завершается.

Логи терминала backend содержат события SSH connected/disconnected/reconnect
и диагностическую причину без паролей и содержимого ключей. В /ready при сбое
SSH возвращаются component=ssh и detail; при недоступном API модели — component=qwen.

При генерации backend пишет в stdout/journald `qwen_start`, `qwen_success` или
`qwen_rejected`/`qwen_failed`: ID запроса, этап, категорию, тип ошибки схемы,
время и статус. **Тексты объявлений, промпты, цитаты, сырой ответ модели и
ключи не логируются.** Для ошибок в JSON-ответе есть `requestId`, а заголовок
`X-Request-ID` присутствует и при успехе; код также добавляется к видимому
сообщению об ошибке. По коду можно найти безопасную диагностическую запись:

```bash
journalctl --user -u avito-pipeline-backend.service -n 100 --no-pager
```

Прежние ошибки восстановить нельзя: сырой ответ Qwen не сохранялся.

### Туннель вручную

В отдельном терминале, подставив своё подключение:

```bash
ssh -N -T -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:18000:127.0.0.1:8000 user@host
```

В backend/.env:

```dotenv
SSH_TARGET=
QWEN_BASE_URL=http://127.0.0.1:18000/v1
QWEN_MODEL=avito-qwen
```

Такой туннель приложение не создаёт и не закрывает. Без SSH_TARGET и без
QWEN_BASE_URL используется http://127.0.0.1:8000/v1 для прямо доступного API.
При авторизации сервера задайте QWEN_API_KEY отдельно от URL.

## API

### POST /api/categories

```json
{"title":"Ремонт","description":"Укладываю плитку и меняю розетки.","mcId":101}
```

`mcId` — исходная категория 101–106 (если не задан, 101); `title` принимается
для совместимости с формой, **но не используется моделью**. TF-IDF анализирует
первые 6000 символов `description`, как при прежней оценке, и исключает
исходную категорию. Ответ: `{"categories":[{"id":103,"name":"Плиточные работы"}]}`
(состав зависит от модели); при отсутствии подходящих категорий — `[]`.
Это автоматический совет, его нужно проверять и при необходимости редактировать.
Маршрут не вызывает Qwen и доступен независимо от состояния генерации.

`GET /ready` сообщает `categoryGeneration` отдельно от готовности Qwen.

### POST /api/generate

```json
{
  "title": "Услуги мастера",
  "description": "Укладываем плитку и меняем смесители. Работаем только по записи.",
  "categories": [
    { "id": 103, "name": "Плиточные работы" },
    { "id": 104, "name": "Сантехника" }
  ]
}
```

- description обязателен: 1–12 000 символов после удаления крайних пробелов.
- title необязателен, максимум 100 символов. Не служит источником новых фактов.
- categories: от 1 до 6 разных числовых ID 101–106. name необязателен;
  для промпта используется доверенный серверный справочник.
- Необязательный mcId обозначает исходную категорию как контекст. Он не
  исключает явно выбранную пользователем категорию из генерации.

Ответ:

```json
{
  "drafts": [
    { "categoryId": 103, "title": "Плиточные работы", "description": "Укладываем плитку. Работаем только по записи." },
    { "categoryId": 104, "title": "Замена смесителей", "description": "Меняем смесители. Работаем только по записи." }
  ],
  "warnings": []
}
```

Каждая выбранная категория возвращает черновик с непустыми title и description.
Если сведений об услуге в исходнике недостаточно, модель пишет общую заготовку
с полями [Уточните ...]. В warnings появятся categoryId, reason=needs_details и
пояснение о необходимости дополнить сведения. Даже при старом ответе модели
supported=false с null title/text backend возвращает явную редактируемую заготовку.
Если текст или цитаты одной категории не проходят проверку достоверности,
backend заменяет **только этот** черновик безопасной заготовкой с предупреждением;
остальные проверенные черновики сохраняются. Непроверенный текст Qwen не показывается.
Некорректный JSON, неправильный набор категорий или общий сбой API всё ещё дают
ошибку всего запроса: валидных отдельных черновиков в таком ответе не извлечь.
Категории не отбрасываются; порядок черновиков соответствует порядку выбора.

GET /health — жив ли FastAPI. GET /ready — доступен ли туннель/API и есть ли
указанная модель в GET /v1/models. Проверка готовности не запускает генерацию.

Ошибки возвращаются как `{ "message": "..." }`:

| Статус | Значение |
|---|---|
| 422 | Невалидный ввод, повтор категории или недостаточный контекстный бюджет |
| 502 | Ошибка API Qwen, обрезанный/неверный ответ или отклонённый черновик |
| 503 | Qwen занят или не готов |
| 504 | Истёк общий срок ожидания генерации |

В запрос передаются сразу все выбранные категории. По умолчанию допускаются
2 одновременных запроса к модели, таймаут — 90 секунд, включая ожидание слота.
Повторные генерации после ошибок автоматически не выполняются.

## Системный промпт и проверки

Промпт находится в app/prompts.py. Он требует отдельный самостоятельный текст
на каждую выбранную категорию, сохранение полезных деталей и условий,
запрет выдуманных конкретных операций, цен, опыта и гарантий. Не обещает отдельный заказ услуги,
доступной только в пакете. Исходное объявление передаётся как данные в JSON.

В requested_categories передаются серверные id, name, description, examples и
boundaries. Примеры работ объясняют категорию и не считаются фактами исполнителя.
В сообщениях перед основным запросом добавлены три фиксированные few-shot пары:
две подтверждённые услуги с условием пакета, исходник про бани без нужных деталей,
частичный отказ внутри категории и чужие работы. Примеры показывают формат;
их факты нельзя переносить в новое объявление.

Модель возвращает служебные поля supported и evidence. Backend проверяет:

- ровно одну запись на каждый выбранный ID, без лишних категорий;
- заголовки до 50 символов и тексты до 2 000;
- цитаты из исходного description для подтверждённых сведений: допускается
  отличие регистра и пробельных символов, но не перефразирование или новая услуга;
- отсутствие новых чисел и некоторых неподтверждённых рекламных условий;
- завершённость ответа и JSON-схему.

Эти проверки не доказывают полную смысловую достоверность: дословная цитата
может содержать отрицание, а условие из другой части текста — относиться к иной
услуге. Корректное разрешение смысла зависит от модели; черновики нужно проверить
и отредактировать перед публикацией. Этот backend ничего не публикует.

supported теперь означает наличие подтверждения в исходнике, а не разрешение
на создание черновика. Для supported=false evidence пустой, результат помечается
как требующий уточнения. Такой результат нельзя считать подтверждённым исходником.

QWEN_RESPONSE_FORMAT выбирает json_object (по умолчанию), json_schema или none.
Используйте режим, поддерживаемый вашим API. Даже в режиме none backend проверяет
JSON ответа. Если ответ обрезается, проверьте QWEN_MAX_TOKENS (по умолчанию 4096)
и контекстное окно модели.
По умолчанию перед генерацией вызывается vLLM /tokenize со всеми сообщениями,
включая few-shot пары. Из окна вычитаются вход и запас 256 токенов, оставшийся
бюджет ограничивает max_tokens. Если места недостаточно, API просит сократить
исходник или количество категорий, не обрезая текст молча.
Для другого OpenAI-совместимого сервера без /tokenize задайте
QWEN_TOKENIZE_BEFORE_GENERATE=0; тогда лимит нужно учитывать самостоятельно.

## Frontend

Запустить frontend с проксированием:

```bash
cd frontend
npm run dev
```

Frontend по умолчанию проксирует генерацию на http://127.0.0.1:8001.
Для другого адреса задайте API_TARGET при запуске frontend.
Выберите исходную категорию, подберите дополнительные категории с помощью TF-IDF
или выберите их вручную и нажмите «Сгенерировать черновики».
POST /api/generate совместим с текущим клиентом. Подбор категорий в задачу этого
сервиса входит: POST /api/categories использует зафиксированную TF-IDF. Frontend-сервер
проксирует этот маршрут без локальной заглушки вне деморежима. Frontend показывает warnings, в том числе при
частичном успехе. Статус подключения проверяется через /ready.
Старый контракт ml-service POST /generate не является маршрутом этого backend.

## Тесты

```bash
backend/.venv/bin/python -m pip install -r backend/requirements-dev.txt
backend/.venv/bin/python -B -m pytest -q backend/tests
```

Тесты подменяют HTTP-ответы Qwen и не требуют удалённого сервера. Проверяются
контракт frontend, промпт, категории и условия, ошибки и таймауты API, проверка
ответа, готовность модели и управление процессом SSH. Реальная доступность Qwen,
его поддержка JSON-режима и качество черновиков проверяются после настройки
подключения. Сервис по умолчанию запускается на loopback; авторизация входящих
запросов в этом локальном варианте не реализована.
