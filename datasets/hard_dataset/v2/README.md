# Расширенный корпус v2

13 960 записей для классификации микрокатегорий 101–106. Это синтетическое
дополнение к реальным объявлениям, а не измеренное улучшение обученной модели.
Включает все 1 840 примеров v1 и 12 120 новых записей. Повторно добавлять v1 нельзя.

| Файл | Записей | Назначение |
| --- | ---: | --- |
| `train.jsonl` | 8 464 | Обучение |
| `validation.jsonl` | 2 440 | Выбор порогов и параметров |
| `test.jsonl` | 3 016 | Итоговая оценка на других формулировках |
| `challenge.jsonl` | 40 | Независимо написанные пограничные пары из v1 |

## Что добавлено

- 16 семейств вложенных отрицаний: отрицание сообщения, опровержение отказа,
  отрицание опровержения, «не отказываемся», «не только не», отрицательное согласование.
  Сценарии до четырёх смысловых уровней есть и в обучении, и в тесте.
- 6 способов описания статуса каждой услуги. Покрыты все 64 подмножества шести
  предлагаемых категорий. После исключения исходной категории получается от нуля
  до пяти целевых меток.
- Для каждого нового шаблонного примера есть исходная версия, версия с опечатками
  и версия с ошибками согласования, падежей, пробелов и пропущенными запятыми.
- 24 отдельно написанные разговорные записи: «неделаю», «неберу», «не тока»,
  «ни делаю», «ниправда», «разетки», «ложу», уточнение «не не, трубы я меняю».
- Сохранены отрицания отдельных операций внутри одной категории, условия заказа,
  чужие работы, прошлые услуги, цитаты и различие между ремонтом под ключ и одной
  услугой под ключ из v1.

Примеры смысла при `mcId=101`:

| Описание | Цели |
| --- | --- |
| «Неверно, что мы не выполняем укладку керамогранита» | 103 |
| «Ни для кого не выполняем укладку керамогранита» | пусто |
| «Я плитку неделаю, а вот разетки меняю» | 105 |
| «Не тока абои клею, но и сантехнику делаю, трубы меняю» | 104, 106 |

В русском языке число частиц НЕ/НИ не определяет ответ по чётности.
«Никому никогда не делаем» остаётся отрицанием, тогда как отрицание ложного
утверждения может подтверждать услугу. Метки новых сценариев заданы по смыслу
целого высказывания; они не получены поиском ключевых слов или подсчётом частиц.

## Формат и обучение

Основные поля совпадают с v1: `description`, `mcId`, `found_microcategories`
и `offered_microcategories`. Дополнительные поля новых записей:

| Поле | Значение |
| --- | --- |
| `augmentation` | `clean`, `spelling`, `grammar_spacing` или `authored_errors` |
| `clean_item_id` | Ссылка на исходную версию для автоматических искажений |
| `topic` | `nested_negation`, `multicategory`, `colloquial_particles` |
| `negation_depth` | Авторская оценка глубины смысловой конструкции, не число НЕ |
| `semantic_version` | `v2` |

Старые записи v1 не обязаны иметь эти поля. Значение `0` глубины в статистике
означает отсутствие новой аннотации, а не отсутствие отрицания.
`clean` в статистике включает исходные записи v1 без автоматических искажений.

На вход модели подаются только описание и, если модель это поддерживает, `mcId`.
Объяснения, идентификаторы, тип, номер варианта и другие служебные поля раскрывают
разметку и не должны попадать в признаки или пользовательскую часть SFT-примера.

Для классификатора, который получает **только описание**, целями обучения служат
`offered_microcategories`; из предсказанного множества затем удаляется исходный
`mcId`. Для модели с обоими входами целями могут быть `found_microcategories`.
Точность конечного ответа оценивается по `found_microcategories`.

Текущие `ml-service/app/classifier.py` и `avito_compare/scripts/train_baseline.py`
поддерживают только головы 102–106. Для них потребуется проекция обучающих меток
на эти пять категорий; для полного покрытия корпуса требуется добавить голову 101.
Скрипт `prepare_dataset.py` рассчитан на старый формат и случайно делит данные:
**не запускайте его для повторного разделения v2**. Сохраните готовые выборки,
при преобразовании в его формат заполните `labels` из `offered_microcategories`.
Для `train_baseline.py` соответствие файлов: train → train, validation → calibration,
test → validation. Имена здесь различаются, назначение выборок должно сохраняться.

## Проверки и ограничения

Семейство шаблонов, контрастная пара и все её искажённые версии всегда остаются
в одной выборке. Проверены уникальность полных нормализованных описаний,
соответствие меток, ссылки на чистую версию и сохранение логических частиц при
автоматическом искажении. Ошибочно написанные частицы созданы и размечены отдельно.
Исходная категория в каждом варианте контрастной пары одинакова; ответы различаются.

Лексика услуг и логические операции намеренно общие для выборок. Тест проверяет
другие формулировки, но не является независимым корпусом реальных пользователей.
Длинные формальные отрицания — стрессовые примеры; их долю в обучении следует
подбирать по реальной валидации. Короткие формы и шаблоны не заменяют реальные тексты.

Старые спорные наборы и публичный тест организаторов в v2 не включены. Подробности
найденных ошибок и ограничений разметки находятся в [отчёте](../AUDIT.md).

Модель не переобучалась. Автоматические проверки подтверждают свойства данных,
но не доказывают правильность каждой языковой интерпретации и не гарантируют F1.
После обучения измеряйте micro-F1, точное совпадение набора, долю полностью
правильных контрастных пар и устойчивость к искажениям; отдельно — по шести категориям.

## Воспроизведение

Из корня проекта, без сторонних зависимостей:

```bash
python3 datasets/hard_dataset/build_v2.py
python3 -m unittest discover -s datasets/hard_dataset -p 'test_*.py' -v
python3 datasets/hard_dataset/build_v2.py --output-dir /tmp/avito-hard-v2-check
```

`stats.json` содержит seed, распределения, размеры выборок и SHA-256 каждого JSONL.
Повторная генерация с seed 2026 даёт те же файлы побайтно.
