Прочитаны все строки 10 исходных файлов: **13 548 записей**, включая 10 000
объявлений public-train и 208 строк public-test в Parquet. Проверены генераторы
и их правила назначения меток. Это полная автоматическая проверка записей и
проверка логики шаблонов; 10 000 слабых меток не переаннотировались вручную.

Parquet имеет другую схему: `title`, `description`, `categories`. Для проверки
названия категорий сопоставлены идентификаторам, исходная категория принята равной
101 по README организаторов. Номера строк используются как временные идентификаторы
аудита. Исходный Parquet не изменён и не использован для генерации обучения.

## Подтверждённые исправления

В шаблоне «профессия — не другая профессия» генератор мог назначать несколько
положительных категорий, хотя в текст попадала только первая профессия.

| item_id | Прежние метки | Исправленные метки |
| --- | --- | --- |
| neg-0060 | 103, 104, 105 | 104 |
| neg-0223 | 103, 105 | 103 |
| neg-0228 | 103, 104, 106 | 103 |
| neg-0235 | 102, 105 | 102 |

Исправлены `found_microcategories`, `offered` и пояснение в исходном JSONL.
Старые значения сохранены в `legacy_corrections.json`; исправленные записи имеют
`annotation_revision=semantic-audit-v2`. В генератор добавлено полное перечисление
предлагаемых работ, чтобы ошибка не повторялась при последующих запусках.

В старых генераторах также уточнены «откос подправить» и «выровняю стены» до явного
упоминания штукатурки. Случайные буквенные ошибки теперь применяются только внутри
длинных слов и не могут удалить НЕ/НИ/НЕТ. Эти изменения относятся к будущей
генерации: неоднозначные уже сохранённые строки автоматически не переименовывались
и не получали новые метки без достаточных оснований.

## Дубликаты и сомнительные строки

В исходных данных обнаружены 483 группы повторяющихся нормализованных описаний.
Среди них **13 групп имеют несовпадающие целевые метки при одинаковой исходной
категории**; все связаны с публичным тестом. Также 13 групп текстов пересекаются
между public-train и public-test. Это разные показатели; их совпавшие значения
не означают, что речь идёт об одних и тех же группах.

Проверка соответствует входу сервиса: сравнивается `description`, без заголовка.
Отличающийся заголовок может объяснять часть исходной разметки, но не устраняет
противоречие для классификатора, который получает только описание.
Метки публичного теста не исправлялись голосованием или предсказаниями модели.
При объединении реальных выборок нужно учитывать совпадения и `source_item_id`
контролируемых правок, чтобы исходник и его производная не попали по разные стороны
разделения. В v2 эти старые корпуса не импортированы.

После исправления четырёх записей остаются **354 замечания для 248 уникальных
строк**: medium-confidence, предположение о 101 и неоднозначные формулировки.
Это кандидаты на проверку, а не 248 доказанных ошибок. Метки по неопределённым
формулировкам автоматически не менялись.

`audit_before.json` сохраняет результат до исправления четырёх строк и до включения
v2 в проверку. `audit_report.json` проверяет 14 файлов, 27 508 строк с учётом v2:
структурных нарушений и потерянных ссылок `source_item_id` нет. Повторы между v1
и v2 ожидаемы: v2 содержит исходные 1 840 записей. Внутри v2 нормализованных
дубликатов и пересечений семейств между выборками нет.

## Повторная проверка

```bash
python3 datasets/hard_dataset/audit.py
python3 datasets/hard_dataset/audit.py --exclude-v2 --output /tmp/avito-original-audit.json
```

Для Parquet требуется `pyarrow`; без него отчёт явно показывает `unread_files`.
В этой проверке пакет установлен отдельно во временную папку и использована команда:

```bash
PYTHONPATH=/tmp/avito-parquet-audit python3 datasets/hard_dataset/audit.py
```

Все записи отчёта ссылаются на путь, строку и item_id. SHA-256 входных файлов
позволяет проверить, относится ли сохранённый отчёт к текущей версии данных.
