# Сложная семантика ремонтных объявлений

**Актуальная расширенная версия: [v2/README.md](v2/README.md)** — 13 960 записей,
включая исходные 1 840, вложенные отрицания до четырёх уровней, все сочетания
микрокатегорий, опечатки, ошибки согласования и разговорные частицы.
Для обучения используйте файлы из `v2/`; не объединяйте обе версии.
Результаты проверки всех исходных датасетов: [AUDIT.md](AUDIT.md).

Ниже описана исходная версия v1, сохранённая для воспроизводимости.

1 840 синтетических размеченных объявлений, объединённых в 920 контрастных пар.
Формат JSONL совместим по основным полям с `datasets/distillate_dataset/hard_ads_500.jsonl`.
Это данные для классификации услуг, а не эталонные тексты рекламных черновиков.

| Файл | Объявлений | Пар | Назначение |
| --- | ---: | ---: | --- |
| `train.jsonl` | 1 320 | 660 | Обучение, 22 семейства формулировок |
| `validation.jsonl` | 240 | 120 | Подбор порогов, 4 других семейства |
| `test.jsonl` | 240 | 120 | Финальная проверка, ещё 4 семейства |
| `challenge.jsonl` | 40 | 20 | Написанные отдельно пограничные случаи |

Каждая пара содержит одинаковый исходный `mcId`, но разные целевые метки.
Меняется отрицание, ограничение, исполнитель или другой смысловой компонент.
Например, «только устанавливаю розетки, проводку не меняю» всё ещё даёт 105;
«не только укладываем плитку, но и меняем трубы» даёт 103 и 104.

## Основания разметки

Использованы правила из `mvp/innoglobalhack_avito/innoglobalhack_avito/`:
`microcategories-guide.md`, `Innoglobalhack-Avito_2026.md`, `hackathon-evaluation.md`;
контракт и реализация из `ml-service/app/{schemas,classifier,generator}.py`;
структура примеров и генераторов из `distillate_dataset`.
Публичные train/test объявления не копировались, их метки не наследовались.
Внешние API и модель для автоматической разметки не использовались.

- Метки отражают реально предлагаемые исполнителем работы, включая явно доступные работы с условиями.
- Текущая категория исключается из `found_microcategories`.
- Отказ от отдельной операции не исключает остальные работы той же категории.
- «Не только», «не отказываемся», отрицание бесплатности, срока или отдельного заказа не равны отказу от услуги.
- Чужая работа, цитата пожелания клиента, прошлое предложение, гипотетическая возможность и явно обозначенные неактуальные теги не дают положительной метки.
- Собственная бригада, которая выполняет работу по договору исполнителя, считается его предложением.
- Для 101 требуется явное комплексное предложение. «Плитка под ключ» остаётся 103.
- Из общей фразы «ремонт под ключ» не выводятся автоматически конкретные работы 102–106.
- Пустой список — полноценный отрицательный пример.

Разметка синтетическая и задана при составлении смысловых сценариев. `confidence: high`
означает намеренно однозначный сценарий, а не независимую экспертную проверку.
Автоматический валидатор проверяет структуру и согласованность, но не доказывает
правильность понимания русского языка. Результаты на этих данных не заменяют
оценку на реальных объявлениях организаторов.

## Поля записи

| Поле | Смысл |
| --- | --- |
| `item_id` | Уникальный строковый идентификатор |
| `title` | Нейтральный заголовок; модель сервиса использует описание |
| `description` | Полный входной текст |
| `mcId` | Исходная категория |
| `found_microcategories` | Эталон дополнительных категорий: объекты `mcId`, `label` |
| `offered_microcategories` | Все явно предложенные категории, включая исходную, если она предложена |
| `group_id`, `variant` | Идентификатор контрастной пары и вариант 0/1 |
| `type` | Семейство конструкции; в challenge — идентификатор ручного сценария |
| `note` | Объяснение разметки для проверки человеком |
| `confidence`, `provenance` | Происхождение разметки |

Вход модели — только `description` и, если архитектура поддерживает, `mcId`.
Не включайте в признаки `note`, `type`, `group_id`, `item_id`, `variant`, метки
и другие служебные поля: они раскрывают ответ.

## Обучение и оценка

Для текущего TF-IDF-классификатора, который видит только `description`, обучайте
головы на `offered_microcategories`, затем исключайте исходный `mcId` при выдаче
ответа, как уже делает `classify()`. Иначе услуга из исходной категории ошибочно
станет отрицательным обучающим примером. Для модели, которая получает и текст,
и `mcId`, можно использовать `found_microcategories` непосредственно.

В текущем сервисе поддерживаются головы только 102–106. Для них проецируйте
обучающие метки на эти пять категорий. Полная поддержка набора требует отдельной
головы 101 и обновления проверки идентификаторов в сервисе; сами файлы сервиса
не изменены. При оценке пяти голов явно указывайте это ограничение, не выдавайте
результат за метрику по всем шести категориям.

Используйте `train.jsonl` для обучения, `validation.jsonl` для настройки,
`test.jsonl` и `challenge.jsonl` — только для итоговой оценки. Не перемешивайте
файлы с последующим случайным разделением: каждая пара и всё семейство шаблона
удерживаются в одной выборке. Общая лексика услуг пересекается намеренно;
разделение проверяет перенос на другие конструкции, а не на неизвестные слова.
Нормализованные полные тексты не повторяются между файлами.

Рекомендуемые измерения: micro-F1 по целевым категориям, точное совпадение набора,
доля пар с двумя правильными ответами и ошибки на пустых ответах. Синтетические
данные стоит добавлять к реальным обучающим объявлениям; объём примеси выбирайте
на отдельной реальной валидации. В наборе преобладают короткие конструкции с
одной-двумя предлагаемыми категориями; это специализированное дополнение.

## Воспроизведение

Из корня репозитория, Python 3.10+, без сторонних зависимостей:

```bash
python3 datasets/hard_dataset/generate.py
python3 datasets/hard_dataset/generate.py --output-dir /tmp/avito-hard-check --seed 2026
```

Генератор перезаписывает четыре JSONL и `stats.json` в указанной папке.
Одинаковый seed даёт одинаковые файлы. Проверяются уникальность идентификаторов
и текстов, отсутствие пересечения пар и семейств между выборками, допустимость
категорий, исключение исходной категории, длина описаний, различие ответов в
паре и наличие всех шести целевых категорий в каждой выборке.
Распределения меток, исходных категорий, типов и пустых ответов находятся в `stats.json`.
