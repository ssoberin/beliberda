Это разные знаменатели, не расхождение расчёта.

### Теоретический потолок micro-F1 при идентичном входе

Для каждой пары `(normalized_description, source_mcId)` и категории имеется `n` идентичных входов с `k` положительными метками. Произвольный детерминированный классификатор может дать им только одинаковый ответ: если ответ «да», получит `k` TP и `n−k` FP; если «нет», `k` FN. При фиксированном кандидате F1 = `f` выбирать «да» выгодно, когда `2k − f·n > 0`. Бинарным поиском по `f` и последующим точным подсчётом целых TP/FP/FN найден максимум micro-F1 **0.92429022** на всех 208 строках: **293 TP / 46 FP / 2 FN**. Внутри одних конфликтных групп потолок **0.85454545** (141 TP / 46 FP / 2 FN); как минимум **48** решений «строка — категория» внутри таких групп останутся несовместимыми с детерминированным ответом по ключу.

Это **oracle-потолок под текущие метки**, а не оценка достижимого качества новой модели: допускается произвольное запоминание оптимального ответа для каждого из 139 ключей без обучения/обобщения. Учитывает повторяющиеся строки с их весами и все пять категорий, не учитывает дополнительные признаки (например, если реальный классификатор получает `title` или отличает строки по несущественным пробелам). Если человеческая проверка изменит gold, потолок тоже изменится. Само превышение 0.8125 теоретическим максимумом не подтверждает полезность какой-либо предложенной модели.

## Этап 2: слепой Public-набор

С фиксированным seed `20261115` отобраны **150 исходных строк**: все **56 конфликтных**, все **37 остальные строки с хотя бы одной FP/FN** (больше таких строк вне конфликтных групп нет), затем **57 случайных строк** вне этих двух частей без зарегистрированных ошибок. После объединения идентичных `(description, 101)` получается **97 заданий для разметчика**, в том числе 13 конфликтных. Поскольку выбранные группы могут включать дополнительные невыбранные исходные строки, сохранены и `selected_indices` (150 оцениваемых строк), и `original_indices` (все ссылки, всего 165 строк в затронутых группах). Это предотвращает дублирование одного задания, но не теряет связи с исходными строками.

- **Для обычного интерфейса разметки:** `/srv/Hakaton/results/data_quality_audit/annotation/public_blind.jsonl` — `item_id`, полный `description`, `source_mcId=101`, `human_labels: null`, `human_comment: ""`, `original_indices`, `selected_indices`. **Нет** gold, вероятностей, предсказаний или причин отбора. Нужно заполнить `human_labels` списком ID 102–106, например `[]` для отсутствия услуг, и добавить комментарий к неоднозначности; не редактировать индексы и ID.
- **Только для последующего сопоставления, не подключать к интерфейсу:** `/srv/Hakaton/results/data_quality_audit/private/public_reference.json` — исходные gold/predictions, пять вероятностей и порогов для всех связанных строк. `private/` имеет права `700`, сам файл `600`. `private/conflict_groups.json` содержит варианты прежних меток. Не пересылать эти файлы разметчикам.
- После завершения: `python datasets/data_quality_audit/score_human_labels.py /path/to/completed_public.jsonl` из `/srv/Hakaton/innopolis_2026` соответствующим Python-окружением. Скрипт откажется от незаполненных/невалидных меток, рассчитает baseline против новых человеческих и старых gold **на тех же 150 выбранных строках**, сохранит подробности в `private/human_score.json`. Он не изменяет исходный тест и не сравнивает 150 строк как независимую оценку качества.

**Ограничение выборки:** 93 из 150 строк целенаправленно связаны с конфликтом или ошибкой модели. Показатели после человеческой разметки описывают только этот смещённый диагностический набор, **не новый независимый тест** и не оценку качества на всех объявлениях Авито. Для итоговой внешней метрики потребуется отдельная случайная, ранее не использованная выборка с независимой разметкой.

## Этап 3: review train после оценки этапов 1–2

В исходных 3 398 train-записях лексический поиск нашёл **114 кандидатов** с хотя бы одним сигналом. Все 114 вынесены в `/srv/Hakaton/results/data_quality_audit/annotation/train_review.jsonl` (в диапазоне 100–150): полный `description`, **текущие** train-метки, `review_status`, пустое `corrected_labels`, пустой `human_comment`, исходный индекс. Рекомендуемые значения `review_status`: `confirmed`, `corrected`, `uncertain`; для исправления заполнить `corrected_labels` списком ID 102–106, для подтверждения можно оставить `null`, при неопределённости оставить комментарий. Это **открытая проверка существующих train-меток**, в отличие от слепого Public-набора; текущая метка может влиять на решение разметчика. Если нужен независимый второй проход, скрыть `current_labels` в UI.

Сигналы отбора (могут пересекаться): условие/пример рядом с категорией — **95**, отрицание рядом — **18**, упоминание другого специалиста рядом — **4**, положительное и отрицательное упоминание той же категории в разных фрагментах — **2**. `private/train_review_candidates.json` хранит теги и фрагменты, **не** включённые в форму разметчика. Сводка — `train_summary.json`. Это не 114 неверных меток: «при необходимости» может описывать реально предлагаемую работу; «другие специалисты» часто означает **собственную** бригаду, а «не делаем частичный ремонт» не отрицает полный ремонт по категории. На этом шаге не выявлено и не подтверждено количественно число действительно чужих услуг — их должен отличать человек по полному тексту.
