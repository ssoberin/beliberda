# Собственный корпус v3

Текущая ревизия: **2**. Исправления после независимого аудита: [CHANGES.md](CHANGES.md).

Новый корпус для выделения дополнительных микрокатегорий 101–106.
Создан из авторских словарей и сценариев в этой папке. Генератор не читает
public, старые наборы, их метки или предсказания моделей.

| Файл | Записей | Назначение |
|---|---:|---|
| train.jsonl | 3 000 | Обучение |
| validation.jsonl | 600 | Настройка порогов и параметров |
| test.jsonl | 600 | Итоговая синтетическая оценка |
| challenge.jsonl | 144 | 24 авторских сценария × 6 исходных категорий |

Challenge содержит 24 разных описания, а не 144 независимых сюжета. Одинаковое
описание с разными источниками проверяет правильность исключения mcId.
Не добавляйте challenge к обучению и не переносите примеры между выборками.

## Распределения

Распределение числа дополнительных категорий одинаково во всех трёх основных
выборках. Исходный mcId исключён из ответа.

| Категорий в ответе | Доля | Train | Validation | Test |
|---|---:|---:|---:|---:|
| 0 | 12% | 360 | 72 | 72 |
| 1 | 26% | 780 | 156 | 156 |
| 2 | 28% | 840 | 168 | 168 |
| 3 | 22% | 660 | 132 | 132 |
| 4 | 9% | 270 | 54 | 54 |
| 5 | 3% | 90 | 18 | 18 |

76% примеров содержат 1–3 целевые категории, крайние ответы 0/5 составляют 15%.
Каждый исходный ID встречается ровно 500 раз в train и 100 раз в validation/test.
Для каждого количества меток представлены все шесть источников. Частоты целевых
категорий дополнительно выравниваются и публикуются в stats.json.

| Длина описания, символов | Доля | Train | Validation/Test, каждый |
|---|---:|---:|---:|
| 80–249 | 20% | 600 | 120 |
| 250–699 | 35% | 1 050 | 210 |
| 700–1 499 | 25% | 750 | 150 |
| 1 500–3 500 | 20% | 600 | 120 |

90% текстов без внесённого шума, 7% с одной-двумя словарными опечатками, 3% с
лёгкими пунктуационными/пробельными ошибками. Ошибки не удаляют НЕ/НИ и не меняют
область отрицания. Чистые копии грязных примеров отдельно не добавляются.

## Содержание

- 24 варианта описания услуги на категорию: 12 для train, 6 для validation, 6 для test.
- Разный порядок услуг, абзацы, списки и компактные объявления.
- Прямые предложения, условия доступа и записи, отказ от бесплатности, FAQ,
  исправление старого отказа, собственная бригада, «не только».
- Отрицательные упоминания: чужой исполнитель, прежняя услуга, отказ на запрос,
  явно неактуальный SEO-тег. Одно нахождение слова в тегах не считается отказом.
- Длинные тексты содержат технические подробности предложенных услуг и условия
  приёмки, закупки, доступа и оплаты. Услуги могут находиться далеко друг от друга.
- Общие условия заказа занимают не более 35% каждого длинного/развёрнутого текста.
  В workflows.py есть отдельные авторские описания хода работ по каждой услуге,
  а также сборки мебели для примеров вне шести категорий.
- Короткие тексты используют все основные смысловые конструкции. В каждом слое
  по числу меток не менее половины коротких примеров содержат отказ, чужую или
  прежнюю услугу. При пяти целевых категориях в таких примерах исходная явно не предлагается.
- В challenge: частичный отказ внутри категории, разграничение штукатурки и
  малярного финиша, водяного и электрического подключения, комплексного и частного
  «под ключ», технологические предпосылки и смена исходного раздела.

Для каждой записи известны предлагаемые услуги до исключения источника.
Массив evidence сохраняет фразы, статус услуги и позиции в тексте. Одно
предложение может подтверждать две категории, но печатается один раз.
Техническое пояснение одной позиции не означает предложение других
специальностей, упомянутых для разграничения ответственности.
В ревизии 2 технические абзацы описывают работу положительно: отказы от услуг
добавляются только отдельными статусными фразами для отсутствующих категорий.

## Вход и обучение

Вход: только description и mcId, как в постановке хакатона. Заголовки нейтральные.

- Модель с обоими входами обучается на found_microcategories.
- Классификатор только по тексту обучается на offered_microcategories, затем
  исключает исходный mcId из предсказания.
- Итоговые метрики считаются по found_microcategories на всех шести категориях.
- evidence, group_id, construction, noise, length_bin, rationale и другие
  служебные поля запрещено включать во вход модели: они раскрывают ответ.
  Это также относится к context_spans и generic_context_chars.

Существующий baseline с пятью головами 102–106 не покрывает весь этот набор:
для оценки по полному контракту нужна также категория 101.

## Воспроизведение

Python 3.10+, стандартная библиотека; установка зависимостей не нужна.

```bash
python3 -B datasets/own_v3/generate.py
python3 -B datasets/own_v3/quality.py
python3 -B -m unittest discover -s datasets/own_v3 -p 'test_*.py' -v
```

Генератор перезаписывает только train/validation/test/challenge, stats.json и
REPORT.md внутри этой папки. Для проверки отдельно от сохранённых файлов:

```bash
python3 -B datasets/own_v3/generate.py --output-dir /tmp/avito-own-v3-check
```

stats.json содержит seed, SHA-256 и распределения. REPORT.md — краткая статистика.
quality.json — проверка пересечений с SHA-256 входов. quality.py ищет межвыборочные
пары с Jaccard полных множеств 5-грамм слов не ниже 0,8. Это лексическая проверка,
не доказательство отсутствия всех смысловых повторов.

## Ограничения

Распределения выбраны для контролируемого покрытия задачи, а не измерены на
реальном потоке Авито. Длина и число комбинаций не означают независимость всех
сюжетов: словари, технические пояснения и условия заказа переиспользуются.
Формулировки услуг, технические абзацы и контекстные банки разделены между
выборками, однако категории и смысловые операции намеренно общие.

Разметка задана при написании сценариев и проверена на согласованность, но не
прошла независимую двойную ручную проверку. Набор нельзя считать доказанно
репрезентативным для реального потока. Прирост micro-F1 не измерялся:
модель в этой задаче не обучалась.

Измеряйте micro-F1, F1 каждой категории, точное совпадение набора и ложные
положительные на пустых ответах. Отдельно показывайте результаты по длине, шуму,
конструкциям и полным группам challenge. Эталонных рекламных черновиков для
обучения генерации этот корпус не содержит.
