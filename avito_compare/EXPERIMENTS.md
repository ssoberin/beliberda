# Сводка экспериментов классификации микрокатегорий

Задача: по description определить предлагаемые услуги 102–106; исходный mcId исключается из ответа. Базовая архитектура — word + char TF-IDF, пять SGDClassifier. Все F1 ниже — **Micro-F1**. Рабочие веса автоматически не заменялись.

**Выборки:** public после удаления нормализованных повторов: train 3398 / calibration 728 / validation 729. Public test организаторов — отдельные 208 строк. V2: train 8464 / validation 2440 / test 3016 / challenge 40. V3 (`dataset_v3@0882f80`): train 3000 / validation 600 / test 600 / challenge 144 (24 текста × 6 исходных категорий).

## 1. Признаки TF-IDF на public

Одинаковые разбиения, SGD и пороги 0,5. Время — один запуск, включает векторизацию и обучение.

| Изменение | Public validation F1 | Признаков | Обучение, с |
|---|---:|---:|---:|
| Word (1,2), char, sublinear_tf=True | 0,93465 | 46 000 | 7,80 |
| Word (1,3), char | 0,93622 | 46 000 | 8,21 |
| Word (1,3), char_wb | **0,93712** | 46 000 | 6,10 |
| char, лимит 60k / 100k | 0,93326 / 0,93100 | 60k / 100k | 8,50 / 8,45 |
| char_wb, лимит 60k / 100k | 0,93534 / 0,93435 | 60k / 100k | 6,07 / 5,98 |
| char без max_features | 0,92861 | 264 550 | 7,70 |
| char_wb без max_features | 0,93479 | 179 590 | 5,49 |
| sublinear_tf=False: char / char_wb, 46k | 0,92969 / 0,93092 | 46 000 | 8,25 / 5,94 |

**Результат:** char_wb 46k + sublinear_tf=True — лучшая измеренная компактная конфигурация этой серии. Прирост триграмм небольшой (+0,16 п.п.), доверительный интервал включает ноль; убедительного преимущества над биграммами нет. Увеличение словаря не помогло. sublinear_tf=True уже был исходной настройкой, поэтому дополнительно проверяли его отключение.

## 2. Синтетика v2 и смешивание с public

Word (1,3), char_wb, лимит 46k, пороги 0,5.

| Обучение | Public validation 729 | Public test 208 | V2 test 3016 | Challenge 40 |
|---|---:|---:|---:|---:|
| Только public | 0,93712 | 0,81481 | 0,35537 | 0,49020 |
| Только v2 | — | — | 0,46081 | 0,44776 |
| Public + v2 | 0,93002 | 0,79217 | 0,44701 | 0,48889 |

На v2-only лимиты 46k/60k/100k дали **одинаковые модели**: доступно всего 10 692 признака. Старые public-модели 46k/60k/100k без переобучения дали на v2 test 0,35537 / 0,35778 / 0,36515.

**Расширение word (1,3)→(1,6)** на public+v2 со снятием словесного лимита: промежуточные максимумы 3/4/5/6 дали V2 F1 0,44617 / 0,44241 / 0,44152 / 0,44322 против 0,44701 у 46k. При (1,6) public validation снизилась до 0,92716, размерность выросла до 339,5k, размер модели — примерно в 10 раз. Конфликтные группы (source, вектор) исчезли уже при снятии лимита на (1,3), но 1152 сложных списков остались с F1=0. Большие n-граммы проблему не решили.

**Результат:** v2 улучшил свой тест, но ухудшил публичные проверки; рост размерности не оправдан. [V2-only](../output/v2-charwb-comparison/report.md), [парное сравнение](../output/paired-data-evaluation/report.md), [n-граммы до 6](../output/ngram-expansion-experiment/report.md).

## 3. Аудит данных и новые примеры

- Public: 10 000 исходных строк → 4855 после удаления нормализованных повторов; медиана длины 1467 символов против 143 у v2 train. В v2 нет текстов от 1000 символов; в public таких 69,64%.
- V2 сильно шаблонный. По экспертной текстовой эвристике: 23,83% реалистичных, 44,53% сложных правдоподобных, 31,63% искусственных; в test искусственных 56,90%. Это оценка корпуса, не статистика настоящего Авито.
- Главный провал v2 — привязка «да/нет» к конкретной услуге в списке: два типа списков дают 82,81% FN смешанной модели. У 642 строк обнаружены конфликтующие ответы при одинаковых текущих признаках и source; одной настройкой порогов это не исправить.
- V3 расширил длины и лексику: медиана train 648,5 символа, p95 3037, максимум 3498. Есть отрицания и чужие исполнители; явных сценариев сравнения услуг при аудите не нашли. Синтетическое происхождение и повторяемость конструкций сохраняются.
- Добавлены **100 авторских обучающих текстов**: сравнения 30, частичный отказ 20, разные исполнители 20, привязка ответа к услуге 20, время/условия 10. Ещё **20 отдельных контрольных текстов** — 10 новых пар сценариев. Точных и близких копий по проверенному критерию не найдено; 6 проверок данных прошли. Разметка авторская, без независимой человеческой перепроверки.

Источники: [длины](../output/dataset-length-comparison/report.md), [подробный аудит v2](../output/v2-complexity-audit/report.md), [новые данные и правила использования](../datasets/context_pairs_100/README.md).

## 4. Доля синтетики v3: 0 / 20 / 60 / 100%

Public train 3398 всегда сохранён. Синтетический пул: v3 train 3000 + новые 100. Вложенные случайные подвыборки, seed=42, новые пары сохраняются целиком. Word (1,3), char_wb, 18k+28k, sublinear_tf=True, прежний SGD, пороги 0,5. Новые 20 вне обучения.

| Доля / добавлено | Public validation | Public test 208 | V3 test 600 | Новые 20 | Fit, с |
|---|---:|---:|---:|---:|---:|
| 0% / 0 | 0,93712 | 0,81481 | 0,18310 | 0,19048 | 6,16 |
| 20% / 620 | 0,93509 | 0,82059 | 0,60528 | **0,52941** | 7,65 |
| 60% / 1860 | 0,93515 | 0,81938 | 0,66257 | 0,48485 | 8,99 |
| 100% / 3100 | 0,93443 | **0,82232** | **0,68182** | 0,45714 | 10,40 |

**Результат:** перенос на v3 существенно улучшился, на публичной validation потеря 0,27 п.п. При 100% на v3 test: Precision 0,84195, Recall 0,57286, FP 107, FN 425; 15,8% предсказанных положительных меток ошибочны. Модель ≈2,77 MiB; пиковая RAM выросла примерно с 475 до 606 MiB.

**Переобучение:** при 100% синтетический train F1=0,92793 против test=0,68182. На новых 20 качество после 20% падает; это предупреждение об ограниченном переносе, но 10 пар недостаточно для выбора смеси. Разрыв может отражать запоминание шаблонов и различия распределений; причина отдельно не доказана.

## 5. Отдельные эксперименты с эмбеддингами

**Qwen3-Embedding-0.6B, замороженный**, 1024 признака + SGD. Это отдельная серия: alpha выбирали CV на train, пороги — на calibration/validation. Это не Qwen 7B для итоговой генерации; дообучение энкодера здесь не проводилось.

На public validation: Qwen **0,88420** при пороге 0,5 / **0,88842** после калибровки против TF-IDF **0,93712**. На public test 208: Qwen **0,66667 / 0,64345** против TF-IDF **0,81481** в public-серии. Кодирование public-сплитов заняло 403,69 с на T4; после прогрева среднее 85,1 мс на объявление, пик VRAM ≈6,4 GiB. SGD по готовым векторам обучался 2,82 с. [Отчёт](../output/qwen3-embedding-sgd/report.md).

На **v3 test 600**, результаты отдельной серии (в ячейках: порог 0,5 / калибровка):

| Обучение | TF-IDF + SGD | Qwen3-Embedding + SGD |
|---|---:|---:|
| Только public | 0,18310 / 0,26468 | **0,62405 / 0,63949** |
| Только v3 | **0,78188 / 0,79276** | 0,73964 / 0,77100 |
| Public + v3, без новых 100 | 0,69153 / 0,75237 | **0,74630 / 0,77874** |

**Результат:** эмбеддинги лучше переносятся на незнакомые формулировки v3 и выигрывают на смеси, но уступают на public и требуют существенно больше ресурсов. На чистом v3 TF-IDF лучше. На challenge смешанный Qwen дал 0,77612 / 0,79412 против TF-IDF 0,74627 / 0,71053. Это отдельные протоколы и составы обучения; их нельзя смешивать с серией долей выше. ## Ограничения и следующие шаги

Public 729 — **validation, не финальный тест**. Public test 208 содержит 13 групп с противоречивыми метками и 20 строк, пересекающихся с фактическим public train; отдельно сохранялись оценки очищенных 114, которые тоже не являются репрезентативной заменой. Проверочные наборы уже использовались в сравнениях; нужен независимый финальный контроль. Измерения времени одиночные; качество на реальном потоке Авито не установлено.

Пока сохраняем компактный TF-IDF как точку сравнения. Следующие проверки: разбиение по семействам сценариев, разбор ошибок и неоднозначных меток, затем регуляризация SGD и калибровка порогов на предназначенных для этого частях. Эти шаги **предложены, ещё не выполнены**. Снижение порогов без проверки может увеличить FP. Рабочую модель по итогам серий не заменяли.
