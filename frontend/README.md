# Frontend

Форма создания черновиков объявлений об услугах. Кнопка **«Создать»** запускает
подбор категорий и генерацию через единый `POST /api/create`. Готовые черновики
появляются по мере обработки, в том числе для одного исходного объявления.
Карточки можно редактировать и копировать, пока остальные ещё создаются.

HTML, CSS и JavaScript ES modules, Node.js 22+. Установка npm-пакетов не нужна.

## Запуск

Сначала запустите backend из корня проекта (настройки в
[backend/README.md](../backend/README.md)):

```bash
backend/.venv/bin/python -B -m uvicorn backend.app.main:app \
  --host 127.0.0.1 --port 8001 --env-file backend/.env
```

Затем:

```bash
cd frontend
npm run dev
```

Откройте http://127.0.0.1:5173. Заполните описание и нажмите «Создать» или
загрузите JSON/CSV/TXT в поле в начале формы. В форме всегда видны
«Название объявления» и единое поле «Описание услуги»: в него можно ввести
текст или вставить JSON/CSV, формат определяется автоматически. Категории появляются только в результатах,
после автоматического определения услуг. Для этого backend использует TF-IDF
и требует `CLASSIFIER_MODEL_PATH`. Для ручного ввода исходный `mcId` равен 101;
для файла можно передать свой `mcId`. Автоподбор исключает исходную категорию.

В интерфейсе заголовки и тексты генерируются автоматически после нажатия
«Создать». Если дополнительных услуг нет, возвращается `drafts: []`.
Режим без генерации текста доступен через API (`?generateText=false`).

## JSON / CSV

Нажмите голубую кнопку «Загрузить файл» или перетащите JSON/CSV/TXT в область
загрузки в начале формы. Данные файла появятся в поле «Описание услуги».
Расширение файла определяет формат, а при вставке в поле JSON определяется
по структуре, CSV — по заголовку description, остальное — как обычное описание.
Списков выбора режима и формата нет. Кнопка «Убрать файл и ввести описание
вручную» очищает загруженные данные.
Лимиты: **100 объявлений, 5 МБ**, каждое описание до 12 000 символов.
Файл передаётся в backend одним запросом. Категории определяются отдельно
для каждой записи автоматически.
При отсутствии `mcId` используется 101. `testcase` сохраняется в результатах.

JSON: одиночный объект, массив объектов или `{"items": [...], "generateText": true}`.
Интерфейс использует генерацию текста (`generateText=true`), независимо от значения в файле.

```json
[
  {"testcase": "case-001", "description": "Меняем смесители и сифоны.", "mcId": 101},
  {"testcase": "case-002", "description": "Укладываем плитку на стены и пол.", "mcId": 101}
]
```

Для явного выбора в JSON добавьте `"categories": [{"id": 104}]`.
Поле «Название объявления» передаётся как `title` (до 100 символов).
Для JSON/CSV оно заполняет отсутствующие названия; собственные `title`
записей сохраняются. Обычный текст, включая TXT-файл, отправляется как одно
объявление вместе с введённым названием.

CSV — UTF-8, с BOM или без него; поддерживаются кавычки, переносы строк внутри
полей и двойные кавычки. Обязателен столбец `description`, необязательны
`testcase`, `title`, `mcId`. Разделитель — запятая или точка с запятой.

```csv
testcase,description
case-001,"Штукатурим стены, меняем смесители и сифоны."
case-002,"Собираем шкафы."
```

Во время создания видны этапы определения услуг и генерации, полоса прогресса,
счётчик обработанных объявлений и прошедшее время. Для одного объявления
прогресс учитывает завершённые категории. Обрыв соединения помечает процесс
как прерванный и сохраняет частичные результаты.
Результаты сгруппированы по исходным объявлениям, видны ошибки.
Ошибка одной категории или записи не останавливает остальные. При обрыве
соединения уже полученные карточки сохраняются, интерфейс сообщает о неполной
обработке. Изменение исходных данных отменяет предыдущий запрос.

Кнопки «Скачать JSON» и «Скачать CSV» доступны во время обработки и после неё.
Экспорт учитывает правки в карточках. Незавершённые записи отмечаются в JSON
`incomplete: true`. CSV соответствует примеру ответа:
`testcase,microcats,descriptions`; последние два поля содержат JSON-массивы.
Для записей с ошибками или незавершённой обработкой добавляется столбец `error`.

## HTTP-контракт

- `GET /api/status` — состояние backend, Qwen и TF-IDF.
- `POST /api/create` — единая точка создания, `application/json` или `text/csv`.
- `Accept: application/x-ndjson` — поток событий `start`, `categories`, `drafts`,
  `category_error`, `item_done`, `done`; `heartbeat` поддерживает соединение.
- `index` связывает событие с исходной записью; `testcase` передаётся, если задан.
- `drafts` содержит готовые результаты `[{mcId, title, text}]`. `item_done`
  содержит полный итог записи, `completed` и `total` — прогресс. Он не должен
  повторно добавляться к уже показанным черновикам из событий `drafts`.
- Без потокового Accept возвращается JSON: `{"drafts": [...]}` для одиночного
  объекта и `{"results": [{"index": 0, "testcase": "...", "drafts": [...]}]}` для пакета.
- `?generateText=false` отключает генерацию текста и имеет приоритет над JSON.

Прокси передаёт части ответа сразу, учитывает обратное давление и отменяет
upstream при закрытии браузерного запроса. Таймаут бездействия — 120 секунд,
общего лимита на время обработки всего пакета нет. Уже начатое вычисление
на сервере Qwen может продолжиться после отмены HTTP-запроса.

Прежние `/api/categories` и `/api/generate` оставлены для совместимости.
Основная форма их не вызывает. Категории выбираются классификатором до Qwen;
Qwen пишет отдельный черновик для каждой выбранной категории и не проверяет
цитаты или `supported/evidence`. При успешной генерации редактору остаётся
проверить факты и условия перед публикацией. Пустые заготовки не подставляются.
Обычно все категории одной записи генерируются одним запросом к Qwen; при
технической ошибке модель повторно вызывается по категориям, чтобы сохранить
доступные черновики. Формат ответа и набор категорий проверяются технически.

Адрес backend и порт frontend можно изменить:

```bash
API_TARGET=http://127.0.0.1:8002 PORT=5174 npm run dev
```

HOST по умолчанию 127.0.0.1, PORT — 5173. Ключи и параметры SSH в браузер не передаются.
При недоступном backend форма повторяет проверку подключения каждые 5 секунд.

## Демонстрационный режим

```bash
MOCK_API=1 npm run dev
```

В форме явно отмечен деморежим. Qwen не используется; ключевые слова и тестовые
тексты из `scripts/mock-api.mjs` предназначены для проверки интерфейса.

## Проверка и сборка

```bash
npm test
npm run build
npm run preview
```

Сборка копирует клиентские файлы в `dist/`. Preview использует тот же прокси и
настройки, что dev. При размещении `dist/` на другом сервере настройте
`/api/status` и `/api/create` отдельно: Node-сервер в статическую сборку не входит.
Внешний reverse proxy должен отключать буферизацию для NDJSON и пропускать
`X-Accel-Buffering: no`.
