# Frontend

Локальная форма создания объявлений по референсу Авито: адаптивная вёрстка,
подбор категорий, ручной выбор и редактируемые результаты генерации.
HTML, CSS и JavaScript ES modules; сторонних зависимостей нет.
Оригинальный HTML использован как референс, его внешние скрипты и аналитика не подключены.

## Запуск

Нужен Node.js 22 или новее. Устанавливать npm-пакеты не требуется.

```bash
cd frontend
npm run dev
```

Открыть **http://127.0.0.1:5173**. По умолчанию сервер принимает реальные POST-запросы
и отвечает локальными заглушками. Для проверки введите описание:
«Укладываю плитку, устанавливаю сантехнику и меняю розетки», нажмите
«Сгенерировать категории», затем «Сгенерировать объявления».
Будут выбраны категории 103, 104, 105 и созданы три черновика.
Можно изменить выбор, отредактировать черновики и скопировать их текст.

Заглушка подбирает категории по ключевым словам и вставляет исходное описание
в каждый черновик. Это демонстрация интерфейса, а не результат работы ML.
Если совпадений нет, вернётся пустой список; категории можно выбрать вручную.
Справочник: `src/catalog.js`, логика заглушек: `scripts/mock-api.mjs`.

## Контракт API

Адреса запросов заданы в `src/api.js`. Запросы и ответы — JSON.
Категории из ответа автоматически заменяют текущий выбор; новые категории
с сервера также добавляются в интерфейс. ID может быть числом или строкой.

### `POST /api/categories`

Запрос (название необязательно, описание обязательно, до 12 000 символов):

```json
{
  "title": "Услуги мастера",
  "description": "Укладываю плитку и устанавливаю сантехнику"
}
```

Ответ:

```json
{
  "categories": [
    { "id": 103, "name": "Плиточные работы" },
    { "id": 104, "name": "Сантехника" }
  ]
}
```

Клиент также принимает массив категорий без обёртки и простой массив строк.
Для строк ID совпадает с названием. Основной контракт — объекты с `id` и `name`.

### `POST /api/generate`

Запрос:

```json
{
  "title": "Услуги мастера",
  "description": "Укладываю плитку и устанавливаю сантехнику",
  "categories": [
    { "id": 103, "name": "Плиточные работы" },
    { "id": 104, "name": "Сантехника" }
  ]
}
```

Ответ:

```json
{
  "drafts": [
    { "categoryId": 103, "title": "Плиточные работы", "description": "Укладываю плитку." },
    { "categoryId": 104, "title": "Сантехника", "description": "Устанавливаю сантехнику." }
  ]
}
```

Ошибки: HTTP 4xx/5xx и `{ "message": "Понятное описание ошибки" }`.
Пустые результаты, недоступность сервера и неверный JSON отображаются в форме.
Изменение исходных данных отменяет текущий запрос, чтобы старый ответ не перезаписал новый выбор.

## Подключение backend

```bash
API_TARGET=http://127.0.0.1:8001 npm run dev
```

В этом режиме заглушки отключены, запросы проксируются на тот же путь:
`http://127.0.0.1:8001/api/categories` и `http://127.0.0.1:8001/api/generate`.
CORS в локальной разработке настраивать не нужно.

**Существующий `ml-service` пока имеет другой контракт** (`POST /generate`, поля
`description` и `mcId`, ответ с `drafts[].text`). Для его подключения понадобится
адаптер или новые backend-роуты с контрактом выше. Эта задача добавляет только
frontend и его локальные заглушки, существующий ML-сервис не меняет.

## Проверка и сборка

```bash
npm test
npm run build
npm run preview
```

Сборка копирует клиентские файлы в `dist/`. Preview открывается на том же порту
и тоже поддерживает заглушки или `API_TARGET`. `HOST` и `PORT` задают адрес и порт
dev/preview-сервера; по умолчанию это `127.0.0.1:5173`.

Для размещения `dist/` на другом сервере настройте маршруты `/api/*` отдельно:
в статическую сборку Node dev-сервер и заглушки не входят. Это локальный
сервер разработки, а не готовая конфигурация production-сервера.
